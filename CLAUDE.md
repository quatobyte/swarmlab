# SwarmLab

Модульный 3D-симулятор роевых систем. Ядро + модули-сценарии. Сейчас строится ядро и модуль пчёлок (Swarm Logic); карьерная техника и урбанистика — позже, их не трогаем.

Работаем по вехам M0–M6. Текущая веха и её статус — в `docs/ROADMAP.md`.

## Документы — когда читать

- `docs/ROADMAP.md` — **перед началом любой задачи**: какая веха текущая, что в неё входит, критерии приёмки.
- `docs/ARCHITECTURE.md` — когда создаёшь модуль, файл или зависимость между пакетами; когда трогаешь протокол агент↔ядро, тики, реплеи, масштабирование.
- `docs/BEES_SPEC.md` — когда реализуешь любую механику пчёлок, API игрока, параметры по умолчанию.
- `docs/PRD.md` — когда решаешь, входит ли что-то в объём работ.
- `docs/PLAYER_API.md`, `docs/CHEATSHEET.md` — когда меняешь `swarmlab/bees/api.py`: обнови справочник, памятку и подсказки редактора (`tools/gen_api_hints.py`).
- `docs/DECISIONS.md` — когда хочется поменять стек или принятое решение; новое решение дописывается туда же.

## Инварианты (нарушение = баг)

- **Ядро не знает о модулях.** `swarmlab.core` не импортирует `swarmlab.bees`. Модуль подключается через контракты из `core`.
- **Физика только через `PhysicsBackend`.** MuJoCo импортируется только внутри `swarmlab/bees/physics/`.
- **Состояние мира — массивы NumPy** (структура массивов). Горячий цикл физики векторизован: силы, автопилот, энергия считаются для всех тел одной операцией.
- **Детерминизм.** Вся случайность — из `core.rng` с seed матча. В симуляции нет `time.time()`, `random` без seed, итерации по `set`. Один seed + одни скрипты → одинаковый хеш реплея на одной машине.
- **Код игрока — только в отдельном процессе-раннере** и только через протокол «пакет сенсоров → пакет команд». Ядро никогда не делает `exec`/`import` кода игрока у себя.
- **`step()` может быть генератором.** `yield` = ждать выполнения команды (DECISIONS 57). Без `yield` семантика прежняя. Менять её можно только с записью в `docs/DECISIONS.md`.
- **Headless-первично.** Симуляция запускается без графики и сети (`swarmlab run ... --headless`). Вьюеры и сервер — клиенты ядра.
- **Windows-first.** Пути через `pathlib`, команды в документации — для PowerShell, `multiprocessing`/`subprocess` совместимы со spawn.

## Соглашения

- Python ≥ 3.10, `pyproject.toml`, зависимости в нём. Окружение `.venv`.
- Код, имена, API — на английском. Docstrings, комментарии в примерах для игроков, UI, документы — на русском.
- Параметры механик — в YAML-конфигах (`configs/`), не константами в коде.
- Тесты — `pytest` в `tests/`; линтер — `ruff`. Перед завершением задачи: `pytest` и `ruff check` зелёные.

## Как работать над вехой

1. Прочитай промт вехи (`prompts/M*.md`) и её раздел в `docs/ROADMAP.md`.
2. Составь план и покажи его до написания кода.
3. Реализуй; каждый критерий приёмки закрывается тестом или командой, которую можно запустить.
4. Веха готова, когда **каждый** критерий приёмки проверен и результат проверки показан. Обнови статус в `docs/ROADMAP.md`, предложи текст коммита. Следующую веху не начинай.
5. Если решение расходится с документами — остановись и спроси; после согласования обнови документ (`DECISIONS.md` + профильный).
