## Согласованные решения (что строим)

### 1. Логотип
Из заголовка лобби убрать овал (`<span class="logo">` в `web/index.html`, стиль `.logo` в `web/style.css`). Остаются «SwarmLab» и подпись «рой пчёл». Favicon вкладки — не трогать.

### 2. Редактор в духе MakeCode (micro:bit)
Тёмная тема остаётся; Python-режим (CodeMirror) по поведению не меняется.
- **Блоки крупные и скруглённые:** рендерер Blockly `zelos`. Проверь размеры полей, галочку «ждать», выпадающие списки, подсветку ошибок (`.sl-error`, `.sl-warning`, `.sl-dup` — у `zelos` другая разметка пути блока).
- **Категории:** иконка у каждой категории (свой маленький SVG или символ — без внешних шрифтов и CDN), цветная полоса, крупнее и контрастнее. Иконки и подписи категорий — в `blocks_ru.js` (`CATEGORIES`).
- **Поиск блока по названию** — поле над категориями; результат — динамическая категория «Найдено» с блоками, у которых подпись (`API_RU`, `CUSTOM_RU`, имена встроенных блоков из `Blockly.Msg`) содержит строку. Без плагинов вне vendored Blockly.
- **Верхняя панель редактора:** переключатель «Блоки | Python» по центру; кнопки «↶ Отменить» / «↷ Повторить» (Blockly `workspace.undo(false/true)`, в Python — CodeMirror); имя проекта (имя скрипта без `.py`); на видном месте «⬇ Экспорт проекта» и «📂 Открыть проект…». Остальное («Сохранить», «Сохранить как…», «Новый…», выбор файла, «Памятка», «Меню») — сохранить, можно сгруппировать.
- **Раскладка:** 3D-вьюер слева и поменьше, блоки (или код) — главная область справа; панель «Матч» и логи — внизу. Разделители (`--ew`, `--dh`) работают как раньше, раскладка запоминается.
- **Подсказки новичку:** в пустой программе (нет блоков в `DO`) — надпись «перетащи сюда команду» внутри блока программы или рядом; у категорий — короткая справка (`tip` в `CATEGORIES`), видна при наведении.

### 3. Проект — файл `.swarm`
- JSON: `{"format": 1, "name": "my_bees", "created": "2026-10-23T12:00:00", "mode": "blocks" | "python", "code": "<текст .py>", "blocks": {<workspace>} | null}`. `blocks` — только при `mode: "blocks"`. Только рой (один скрипт улья): без настроек матча и без соперников.
- **«⬇ Экспорт проекта»** (редактор) — скачать `<имя>.swarm` через браузер (Blob). Если в блоках ошибки или Python не проходит `ast` — экспорт разрешён, но с предупреждением «Проект с ошибками: …» (подтверждение).
- **«📂 Открыть проект…»** (редактор) — выбрать `.swarm`, получить его как новый свой скрипт (имя — из `name`, при совпадении — предложить другое), вместе с блоками; режим — из `mode`.
- Проверка формата файла — на сервере и в браузере: неизвестный `format`, нет `code`, битый JSON → понятная ошибка.

### 4. Меню (лобби): проекты
- **Загрузить проект** (`.swarm`, кнопка и перетаскивание в окно — рядом с реплеями `.swr`). Сервер кладёт проект в папку `projects/` (рядом с `replays/`, `ServerConfig.projects`): `<имя>.py` + `<имя>.blocks.json` (если блоки) + `<имя>.swarm` (оригинал). Имена проверяются как у скриптов редактора (DECISIONS №47), запись атомарная, размер ограничен. **Одинаковое имя с другим содержимым не перезаписывает**: новый проект получает суффикс даты (`my_bees-20261023-1200`). Одинаковое содержимое — тот же проект.
- В редакторе папка `projects/` не видна.
- **Список загруженных проектов** в меню: имя, режим (🧩 / Python), дата; у каждого — «Открыть в редакторе» (копия в `examples/bees/` под новым именем, свой скрипт, с блоками).
- **Предупреждение о чужом коде** перед первым запуском: «Код из этого проекта выполнится на вашем компьютере. Открывайте только проекты от тех, кому доверяете.» + «Запустить» / «Отмена». Браузер запоминает sha256 содержимого `code` (localStorage, ключ `swarmlab.trusted`); изменённый файл спросит снова. Проверка — в браузере (это не защита, а честное предупреждение; DECISIONS 65).
- **Форма матча в меню** — как панель «Матч» редактора (переиспользовать `MatchPanel` из `web/js/modules/bees/editor.js`, не копировать): профиль, seed (по умолчанию случайный, кнопка 🎲), длительность, шершни / пауки / погода, скорость; **у каждого улья** — выбор: встроенный пример (`example_*.py`, `template.py`) или загруженный проект. Две кнопки: «▶ Смотреть матч» (живой 3D) и «Серия…».
- Старая форма «Новый матч» (выбор YAML из `configs/matches`) остаётся.

### 5. Серия матчей
- **CLI:** `swarmlab series <матч.yaml> --n 10 --seed <начальный> [--set ПУТЬ=ЗНАЧЕНИЕ …] [--jobs N] [--out папка]`. Ульи и скрипты — обычными `--set` (`hives=[…]`), как у `run`. Матч i — seed `начальный + i` (i = 0…N−1). Начальный seed не задан — случайный (из `secrets`/`os.urandom` в CLI, вне симуляции — это не нарушает детерминизм матча), печатается и пишется в `series.json`.
- **N:** по умолчанию 10, от 2 до 50.
- **Параллельно:** `--jobs` по умолчанию `max(1, физических ядер − 1)`; каждый матч — отдельный процесс (как воркер живого матча, spawn-совместимо, Windows). Результат не зависит от числа процессов.
- **Хранение — всё и навсегда**, удаления в интерфейсе нет: `replays/series/<YYYYMMDD-HHMMSS>-<проект>/`:
  - `s<seed>.swr` — реплей каждого матча (как у `swarmlab run`, с хешем);
  - `series.json` — `{format, created, match, overrides, profile, duration_s, start_seed, n, jobs, hives: [{team, name, script, sha256}], matches: [{seed, replay, hash, state, results…}], summary}`; `sha256` — хеш текста кода улья (какая версия алгоритма играла);
  - `results.csv` — таблица ниже (UTF-8 с BOM, разделитель `;` — откроется в Excel на русской Windows; pandas — `sep=";"`).
- **Таблица (строка на матч, по улью проекта/первому улью; в JSON — по всем ульям):** seed, место, мёд, доставлено нектара, живых пчёл в конце, гибели (энергия / шершень / паук), ошибки кода (исключения `agent_errors`, пропущенные тики `missed`, превышения бюджета `over_budget`). Строки с ошибками кода подсвечены. Итог: средние, число побед, худший seed (по месту, потом по мёду), сколько матчей с ошибками кода. У каждой строки — «Смотреть» (открыть `s<seed>.swr` во вьюере с перемоткой).
- **Гибели по причинам** в `score()` сейчас нет — добавить счётчики (`deaths_energy`, `deaths_hornet`, `deaths_spider`, по причине из `kill(..., cause)` и `_ground_deaths`) в строки `ScoreBoard`. **Проверь**, не входит ли счёт в хеш реплея: тест M7a `test_step_without_yield_gives_same_replay_hash_as_before_m7a` сверяет хеш `demo.yaml` — если счёт в хеше, хеш изменится; тогда остановись и согласуй (обновить эталон с объяснением в отчёте).
- **Сервер:** `POST /api/series` `{match, overrides, start_seed?, n, jobs?, scripts?[]}` → `{id}`; синтаксис скриптов — проверка как у `POST /api/matches`; серия — фоновый процесс (тот же код, что CLI); `GET /api/series` (список прошлых — из папок `replays/series/`), `GET /api/series/{id}` (`series.json` + прогресс), `POST /api/series/{id}/stop` (остановить: дописанные матчи остаются, недописанные реплеи удаляются, `state: "stopped"`), `GET /api/series/{id}/replays/{seed}`. Прогресс — опросом `GET` раз в 1 с или WS — на твоё усмотрение, запиши в DECISIONS.
- **Где кнопка:** «Серия…» и в меню (форма из п. 4), и в панели «Матч» редактора (тот же код и та же таблица; в редакторе таблица открывается поверх вьюера). Прогресс «матч 3 из 10», «■ Остановить серию». В меню — **список прошлых серий** (дата, проект, N, начальный seed, побед / с ошибками): открыть таблицу, смотреть реплеи.

## Решения (дописать в `docs/DECISIONS.md`, дата 23.10)

- **63** — Проект — файл `.swarm` (JSON `{format, name, created, mode, code, blocks?}`), только рой без настроек матча и соперников: настройки и соперники выбираются при запуске, чтобы проверять код на разных условиях. Экспорт с ошибками — разрешён с предупреждением. Отвергли: zip; `.py` без блоков; проект с настройками или с кодом соперников.
- **64** — Загруженные проекты — папка `projects/` (не видна в редакторе), имя проверяется как у скриптов, другое содержимое под тем же именем — новый проект с суффиксом даты; «Открыть в редакторе» копирует в свои скрипты. У каждого улья в меню — пример или проект. Отвергли: класть в `examples/bees/`; временная папка.
- **65** — Чужой код из проекта выполняется на этом компьютере (раннер изолирует от симуляции, не от системы): перед первым запуском — предупреждение, браузер помнит sha256 кода; изменённый файл спрашивает снова. Отвергли: без предупреждения; только блочные проекты; предупреждение каждый раз.
- **66** — Серия: `swarmlab series` (CLI первичен, сервер и меню — клиенты), N = 10 (2–50), seed подряд от начального (по умолчанию случайного), параллельно `max(1, физ. ядер − 1)` процессов; все реплеи и `series.json` (с sha256 кода ульев) + `results.csv` в `replays/series/<дата>-<проект>/` хранятся всегда, удаления в интерфейсе нет — для анализа игр и доработки алгоритмов; таблица: seed, место, мёд, доставлено, живые, гибели по причинам, ошибки кода; «Смотреть» — реплей. Серия — и в меню, и в редакторе. Отвергли: независимые случайные seed; фиксированный набор 1…N; перезапуск живого матча вместо реплея; удаление старых серий.
- Плюс отдельной строкой — UI-решения редактора (рендерер `zelos`, иконки, поиск, раскладка с вьюером слева, тёмная тема сохраняется), когда будут реализованы; способ передачи прогресса серии (опрос или WS).
