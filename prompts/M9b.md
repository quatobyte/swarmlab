**Указания:**
- **План сначала.** Покажи план до кода: как запускается раннер под nsjail, какие права нужны контейнеру, где лимиты и очередь, какие тесты где и как их запускать на Linux. Жди «ок».
- **Песочница (№93).** Протокол раннера не меняется: nsjail оборачивает тот же `python -m swarmlab.runner` (`ProcessLink`). Обёртка — общий механизм ядра «префикс команды запуска раннера» из настроек (ядро не знает слова nsjail в коде, а настройка — в `public.yaml`); без `--public` префикса нет. Внутри песочницы:
  - нет сети (отдельное сетевое пространство без интерфейсов);
  - файловая система только для чтения: интерпретатор и пакет — read-only, скрипт игрока — read-only, запись только во временную папку раннера;
  - нет доступа к базе, папкам других пользователей, `.env`, домашней папке;
  - окружение процесса — только нужные переменные (`PYTHONHASHSEED`, `PYTHONIOENCODING`, `PYTHONUNBUFFERED`, путь к пакету): секреты сервера в раннер не передаются — сейчас `ProcessLink.start` копирует всё `os.environ`, это надо закрыть;
  - лимиты: процессор, память, число процессов, размер файлов, время жизни; отдельный непривилегированный пользователь.
- **Права контейнера.** Без `docker.sock` и без `--privileged` (№93). nsjail внутри Docker обычно требует пространств имён пользователя — найди минимальный набор (`--security-opt`, `--cap-add`), запиши его в `ARCHITECTURE.md` §7.1 и объясни Лео в отчёте. Если без `--privileged` не выходит — **остановись и спроси Лео** (варианты: bubblewrap, `unshare` + `setrlimit`, другие настройки ядра хоста); не ослабляй решение молча.
- **Dockerfile** (Linux) — в `master`, общий для любой ветки: ставит пакет ветки (`pip install .`), nsjail (пакет дистрибутива или сборка в отдельной стадии; версию записать), запускает `swarmlab serve --public` от непривилегированного пользователя. Данные — в томе. Образ с модулем собирается в ветке модуля тем же Dockerfile.
- **Лимиты и очередь (№94)** в публичном режиме, числа — в `public.yaml`: один живой матч на пользователя (новый вытесняет только его старый), всего 4 на сервер, остальные — очередь с номером в интерфейсе и автостартом; профили только из разрешённого списка (`small`, `medium`); матч без зрителей 60 с останавливается и дописывает реплей; серии — `n ≤ 10`, `jobs 1`, одна на сервер. Локальный режим не меняется (`--max-matches`, вытеснение как раньше).
- **Тесты на Linux (№95).** Тесты песочницы помечены (`pytest.mark.sandbox`) и на Windows пропускаются с понятной причиной. Запуск на Linux — одной командой в контейнере (опиши её в `README.md`). Если на машине Лео нет Docker — прогоняй их на сервере Лео (`ssh root@5.231.230.25`, вход по ключу) во **временном** контейнере с уникальным именем, удаляй его после прогона; работающие контейнеры `caddy`, `amnezia-*` и их сети не трогай, порты наружу не открывай.
- **Где что делается (№98).** Ядро, сервер, Dockerfile, тесты песочницы и лимитов без матчей — в `master`. Тесты с настоящими матчами (вредный код игрока в матче, очередь, остановка без зрителей), замер — в `bees` после `git merge master`.
