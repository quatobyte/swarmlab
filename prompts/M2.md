Веха M2 — код игрока и экономика улья.

Прочитай `CLAUDE.md`, `docs/ROADMAP.md` (M2), `docs/ARCHITECTURE.md` §3.3–3.4, `docs/BEES_SPEC.md` §3, §4, §5, §11. Посмотри, что сделано в M0–M1.

Задача: всё из «Входит» M2 с закрытием каждого критерия приёмки.

Указания:
- План сначала: схема сообщений `SensorBatch`/`CommandBatch` (поля, типы), жизненный цикл раннера (старт, рукопожатие, тик, таймаут, перезапуск, завершение), как ядро параллельно ждёт несколько раннеров. Жди «ок».
- `swarmlab/bees/api.py` — это то, что читают дети. Docstrings и подсказки типов на русском, имена на английском, автодополнение в PyCharm/VS Code должно показывать все сенсоры и команды. Базовые классы без переопределённого `step()` дают простое встроенное поведение.
- Код игрока импортируется только в процессе раннера. Протокол — msgpack с 4-байтной длиной по stdin/stdout; stdout игрока (`print`) перехватывается в лог, а не ломает протокол.
- Windows: `subprocess` с `sys.executable -m swarmlab.runner`, без `fork`. Проверь на Windows, а не только в теории.
- `examples/bees/template.py` — подробные русские комментарии для 12-летнего: что такое тик, что видит пчела, какие команды есть, три подсказки, с чего начать.

Проверка: тесты, `ruff check`; `swarmlab run configs/matches/m2_economy.yaml --headless` с `example_basic.py` — покажи рост мёда по времени (таблица каждые 30 с). Статус M2 → 🟨, текст коммита.
