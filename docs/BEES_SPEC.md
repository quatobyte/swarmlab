# Спецификация модуля «Swarm Logic» (пчёлки)

Все числа ниже — **стартовые значения для балансировки**. Они живут в `configs/bees/defaults.yaml`, а не в коде. Где число выведено из цели («сборщик летает ~4 минуты»), реализуй цель и подбери число, а не наоборот.

Единицы: 1 единица длины = 1 м, время в секундах, масса в кг, сила в Н, энергия в Дж. Нектар и мёд — условные единицы (ед.).

Масштаб игровой, не биологический: пчела размером с мяч, чтобы её было видно на карте 300 м и чтобы физика была устойчивой при dt = 5 мс.

---

## 1. Мир

- **Карта:** квадрат `map_size` (профиль «Средний» — 300×300 м), потолок полёта — 30 м над рельефом.
- **Рельеф:** heightfield MuJoCo, сетка 128×128, fBm-шум из `rng("world")`, перепад до 8 м.
- **Препятствия:** деревья (ствол-капсула + крона-сфера, обе твёрдые), камни (боксы). Плотность из профиля. Не ставятся ближе 15 м к ульям.
- **Цветы:** кластеры (поляны). Цветок — **не физическое тело**: это запись в массиве (позиция, нектар, флаг паука). Пчела может висеть над цветком, цветок пчелу не толкает.
- **Ульи:** 1–3, статичные боксы с «летком» (точка входа). При трёх ульях — вершины треугольника со стороной ~150 м вокруг центра. Цветы распределены так, чтобы у каждого улья были сопоставимые поляны (честность).
- **Границы:** мягкие стенки — сила, возвращающая к карте, + автопилот обрезает цели по границам.
- Генерация полностью определяется seed.

## 2. Физика

### 2.1 Тело пчелы

Свободное тело MuJoCo (freejoint), геометрия — сфера. Вращение не важно для игры: угловые скорости демпфируются, ориентация во вьюере берётся по вектору скорости.

| Параметр | Разведчик | Сборщик |
|---|---|---|
| Радиус, м | 0.20 | 0.25 |
| Масса пустой, кг | 0.05 | 0.08 |
| Макс. груз нектара, ед. (масса) | — | 1.5 (0.06 кг; M6, было 1.0) |
| Макс. тяга `T_max`, Н | 1.2 | 1.8 |
| Цель: крейсерская скорость, м/с | ≈ 8 | ≈ 5 пустой |
| Радиус обзора, м | 25 | 8 |
| Цель: время полёта на крейсерской скорости | ≈ 5 мин | ≈ 4 мин |

Охранников нет (DECISIONS №82). Домашняя пчела не летает и **не имеет физического тела** — она существует только внутри улья и работает без кода игрока (§4.3).

### 2.2 Силы (применяются каждый шаг физики, векторно для всех тел)

- **Тяга** — от автопилота, `|T| ≤ T_max`.
- **Гравитация** — MuJoCo для полной массы пчелы. Груз меняет и вес, и инерцию: масса тела слота меняется на лету (DECISIONS №25; проверено тестом — ускорение при одинаковой силе ∝ 1/m).
- **Сопротивление воздуха** — квадратичное по скорости относительно воздуха:
  `F_drag = −c_d · |v − w| · (v − w)`, где `w` — ветер в точке пчелы.
  `c_d` по типу подбирается из крейсерской скорости: горизонтальный запас тяги `√(T_max² − (mg)²) = c_d · v_cruise²`.
- **Ветер** `w(x, y, z, t)`:
  - базовый вектор по состоянию погоды (см. §6), направление медленно поворачивается;
  - профиль по высоте (степенной закон приземного слоя): `|w|(z) = w_ref · (z_agl / 10)^0.14`, при `z_agl < 1` — как при 1 м;
  - порывы: сумма 3–4 синусоид по времени и координатам с фазами из `rng("weather")` (дёшево, гладко, детерминированно).
- **Дождь:** дополнительная сила вниз `F_rain = k_rain · r²` и множитель сопротивления ×1.3.
- **Мягкие стенки и потолок** — пружина за пределами карты/потолка.

### 2.3 Энергия

Мощность — модель идеального винта (теория импульсного диска): индуктивная мощность растёт как `T^1.5`.

`P = P_idle + k_p · |T|^1.5`, `E -= P · dt`.

`E_max` и `k_p` подбираются так, чтобы выполнялись цели «время полёта» из §2.1. Висение тоже тратит энергию (как у реальных дронов).

При `E = 0` тяга = 0: пчела падает и после касания земли погибает. В улье энергия восполняется за мёд (§4.4).

**Бак** каждой летающей пчелы случаен при рождении: `E_max = E_max(тип) · (1 ± tank_spread)`, разброс равномерный, по умолчанию ±20 % (`energy.tank_spread`), поток `rng("bees.tank")` (DECISIONS №86). Игрок видит энергию в процентах своего бака (`self.energy`) и размер бака (`self.max_energy`, Дж).

**Автовозврат** (DECISIONS №86, только ульи с кодом игрока): летящая пчела с энергией ниже порога улья (`set_home_energy`, по умолчанию `energy.home_energy` = 30 %, 0 — выключено) сама летит домой; ждущая команда получает «не вышло», команды движения не выполняются, пока пчела не заправится дома до `set_refuel_energy` (по умолчанию 100 %). Конец автовозврата увеличивает `epoch` пчелы — раннер начинает её `loop()` сначала.

### 2.4 Столкновения (битовые маски MuJoCo `contype/conaffinity`)

| Тело | Сталкивается с |
|---|---|
| Рельеф, деревья, камни, ульи | всеми пчёлами |
| Пчела | пчёлами (любых ульев), статикой |
| Цветок | ни с чем (не тело) |

Пчёлы внутри улья и погибшие — «припаркованы» (пул тел, см. ARCHITECTURE §3.5) и не сталкиваются.

## 3. Управление

### 3.1 Модель

У каждой летающей пчелы и у улья — метод `loop(self)` (один код на всех пчёл типа). Пчела знает
только то, что рядом. Домашние пчёлы кода игрока не имеют (§4.3). Объекты пчёл живут в раннере
между тиками — можно хранить память в `self`.

**`loop()` по кругу** (DECISIONS №84): раннер выполняет `loop()` снова и снова; один проход — не чаще
раза за тик решений (10 Гц), конец прохода — скрытое ожидание следующего тика. Команды движения
**ждут выполнения сами**, без `yield`: у каждого агента в раннере свой лёгкий поток `greenlet`,
ждущая команда переключает поток обратно в хост, хост переключает потоки строго по порядку `uid`
(улей — последним) — детерминизм не зависит от ОС.

- Команда выполнена — по условию модуля (DECISIONS №61, №87), см. таблицу §3.3; потолок ожидания —
  `program.command_timeout_s` (60 с игрового времени), дальше «не вышло».
- Ошибка в `loop()` — трассировка в лог, пчела останавливается (`stop`), на следующем тике `loop()`
  начинается сначала. Смерть, автовозврат (§2.3) и конец матча закрывают поток: `finally` игрока
  выполняется, команды внутри него не ждут. Новая пчела начинает `loop()` с начала (DECISIONS №58).
- Данные пчелы — свойства только для чтения; `self.pos = …` — исключение с понятным текстом.
- Параметры — секция `program:` (`arrive_tolerance`, `arrive_max_speed`, `command_timeout_s`,
  `search_min_nectar`, `explore_radius`, `collect_place_radius`).

### 3.2 Файл игрока

```python
from swarmlab.bees.api import Collector, Hive, Scout


class MyScout(Scout):
    def loop(self): ...


class MyCollector(Collector):
    def loop(self): ...


class MyHive(Hive):  # необязательно
    def loop(self): ...
```

Раннер находит по одному подклассу каждого типа (если подкласса нет — используется базовый со
встроенным простым поведением). Полный справочник — `docs/PLAYER_API.md`.

### 3.3 Команды

Набор минимальный (DECISIONS №82, №85): только то, что нужно рою, чтобы работать как
мультиагентная система. Выгрузка нектара, работа домашних пчёл, вылет из улья и возврат при
низкой энергии происходят сами. Цель — цветок, пчела, сообщение (место), `Point` или `x, y`;
`speed=` — необязательный параметр всех команд движения.

| Команда | Кто | Ждёт до | Результат |
|---|---|---|---|
| `fly_to(цель)` | все | ближе `arrive_tolerance` к цели автопилота (рельеф + 5 м) и медленнее `arrive_max_speed` | `True`; таймаут — `False` |
| `search(цель)` | все | первый увиденный цветок с нектаром ≥ `search_min_nectar` (пчела зависает) или прибытие | цветок / `None` |
| `explore()` | все | `search` к случайной точке в `explore_radius` от летка (`rng("bees.explore")`) | цветок / `None` |
| `collect(цветок)` | сборщик | конец набора: груз полный или цветок пуст | `True`, если груз полный |
| `collect(место)` | сборщик | подлетев на дальность обзора, выбирает ближайший к месту цветок с нектаром (≤ `collect_place_radius`) и собирает | как `collect`; нет цветка — `False` |
| `go_home()` | все | вход в улей (нектар уже на складе) | `True` (дома — сразу) |
| `refuel(уровень)` | все | дома, энергия ≥ уровня (не дома — сначала `go_home`) | `True`; таймаут — `False` |
| `wait(с)` | все и улей | столько секунд игрового времени (раннер, по времени сенсоров) | — |
| `stop()` | все | не ждёт: висеть на месте (дома — остаться) | — |
| `say(слово, место)` | все и улей | не ждёт (§5.2) | — |
| `mark(цвет)` | все | не ждёт: феромон в клетке под пчелой | — |

**Улей (`Hive`):** `hatch(тип)` — сразу `True`/`False` (мёд и место, списание сразу),
`count(тип)`, `honey`, `time`, `say`, `heard`, `wait`, `set_home_energy(0–90)`,
`set_refuel_energy(%)`. Тип — класс `Scout`, `Collector`, `Worker` (или подкласс игрока).

**Уточнения (DECISIONS №34):**
- Пчёлы начинают матч и рождаются **в улье** (тело припарковано). Команды, отданные в улье, кроме
  `go_home`, `refuel`, `stop`, сначала выводят пчелу наружу — в свободную точку перед летком, не
  больше `hive.exit_per_tick` (3) за тик на улей.
- `go_home` — автопилот к летку; ближе `hive.enter_radius` (1.5 м) пчела входит в улей и **весь груз
  нектара сразу уходит на склад** (событие `delivery`). Леток — на грани +x: пчела позади этой грани
  летит сначала к точке сбоку от улья (зазор `hive.approach_margin` = 2.5 м).
- `collect`: цель — точка над цветком; когда груз полный или цветок пуст, пчела висит над цветком.
- Ошибочные аргументы API ловит в момент вызова (исключение на строке игрока, ARCHITECTURE §3.4).

**Формат команды в протоколе** (`CommandBatch.commands[id]`):
`{"move": [op, *args] | None, "wait": seq, "say": [[слово, x, y] | [слово], …], "marks": [[канал, сила], …]}`;
`op` — `fly_to[x, y, speed]`, `search[x, y, speed]`, `explore[speed]`, `collect[flower_id, speed]`,
`collect_at[x, y, speed]`, `go_home[speed]`, `refuel[level]`, `stop[]` (`speed` — число или `null`).
`wait` — номер ожидания у команды, которую ждёт поток; статус — в сенсорах
`me["wait"] = [seq, состояние, результат]` (ARCHITECTURE §3.3). Улей (`team_command`):
`{"hatch": [kind, …], "say": […], "home_energy": %, "refuel_energy": %}`. Модуль повторно проверяет
команды: битые отбрасываются и считаются; команды движения пчёл на автовозврате не выполняются.

### 3.4 Автопилот

Векторный PD-регулятор для всех пчёл сразу на частоте физики:
`a_des = Kp·(p* − p) + Kd·(v* − v)` → `T = m·(a_des + g) + компенсация сопротивления` → ограничение `|T| ≤ T_max` с приоритетом вертикальной составляющей (сначала удержать высоту, остаток — на горизонталь).

- Реализация (DECISIONS №24): `a_des = Kd·(v_ref − v)`, `v_ref = clip(Kp/Kd·(p* − p), speed)` — в линейной зоне это тот же PD, вдали от цели скорость ограничена. Тяга вниз не создаётся.
- Держит минимальный просвет 1.5 м над рельефом — и под пчелой, и впереди по курсу (точка через `terrain_lookahead_s`).
- Компенсирует известные силы: сопротивление с учётом ветра (датчик `airspeed`) и дождь.
- `avoid_obstacles` (по умолчанию включено): отталкивание от видимых препятствий — потенциальное поле плюс увод вбок по касательной; препятствие, у которого лежит сама цель, не отталкивает. Можно выключить в `fly_to(..., avoid=False)` — для старших, кто пишет свою навигацию.
- `separation` (по умолчанию включено, DECISIONS №27): мягкое расталкивание соседних пчёл; выключается тем же `avoid=False`.

## 4. Экономика улья

### 4.1 Хранилище
Нектар (ед.), мёд (ед.). Старт: мёд 20, нектар 0. **Мёд не появляется сам по себе** — только переработкой принесённого нектара.

### 4.2 Сбор
Сборщик над цветком (горизонтально ≤ 1 м, высота над цветком ≤ 1.5 м, скорость < 0.7 м/с) набирает 0.25 ед./с, пока не полон. Цветок: максимум 3 ед., восстановление 0.01 ед./с.

### 4.3 Переработка
Домашние пчёлы работают сами, кода игрока у них нет (DECISIONS №82). Все домашние улья выполняют одно правило: нектара на складе больше `processing.min_nectar` (0.05 ед.) → перерабатывают; иначе есть личинки → нянчат (§4.5); иначе отдыхают. Игрок управляет ими только числом: `self.hatch(Worker)` в улье.
`скорость = k_proc · √n_process` ед. нектара/с (убывающая отдача), `k_proc = 0.1`. Выход: 1 ед. нектара → 0.5 ед. мёда.

### 4.4 Питание
- Летающая пчела в улье автоматически заправляется: 1 ед. мёда = 4000 Дж, скорость заправки 200 Дж/с.
- Каждая домашняя пчела потребляет 0.002 ед. мёда/с.
- Нет мёда → заправки нет, домашние пчёлы не работают (ни переработки, ни ухода за личинками). Улей с нулём мёда и нектаром на складе так и стоит — вопрос баланса M6.
- Если мёда на заправку всех пчёл в улье не хватает, каждая получает одну и ту же долю.
- Экономика, сбор и заправка считаются на тике решений (10 Гц), векторно.

### 4.5 Выведение
`hatch(тип)` (класс улья `Hive`) ставит личинку в очередь и сразу списывает мёд:

| Тип | Цена, мёд | Базовое время, с |
|---|---|---|
| Разведчик | 3 | 30 |
| Сборщик | 4 | 30 |
| Домашняя | 2 | 20 |

Время выведения = базовое / `√max(1, n_nurse)` — нянчат домашние, когда нектара на складе нет (§4.3). Лимит пчёл улья — `max_bees` из профиля.

Уточнения M2 (DECISIONS №34): очередь растёт **по одной личинке** (голова очереди). Лимит считает всех живых (летающих, в улье, домашних) **и личинок**; `hatch` сверх лимита или без мёда — сразу `False` без списания (модуль проверяет ещё раз, причина отказа — в лог игрока). Отмены личинок нет (DECISIONS №82).

### 4.6 Стартовый состав
5 разведчиков, 15 сборщиков, 10 домашних — у ульев со скриптом игрока; все начинают в улье с полной энергией.

## 5. Сенсоры и связь

### 5.1 Что знает пчела

| Данные (`self.…`) | Содержимое |
|---|---|
| `pos`, `home` | где я и где леток моего улья |
| `energy`, `max_energy` | энергия в % своего бака и размер бака, Дж |
| `nectar`, `is_full`, `at_home` | груз, полный ли, в улье ли |
| `flowers`, `nearest_flower(min_nectar)` | видимые цветы: `pos, nectar, distance` (+ `spider` — только у разведчика ближе 4 м по горизонтали, DECISIONS №89) |
| `bees` | видимые пчёлы: `pos, friend, distance` |
| `heard` | услышанные сообщения (§5.2) |
| `smell(цвет)`, `smell_way(цвет)` | запах под пчелой и точка в 5 м туда, где сильнее |
| `time` | время матча |

«Видимые» = в радиусе обзора типа (дождь: ×0.7). Всей карты пчела не видит. Препятствия, ветер,
погоду и рельеф автопилот учитывает сам — игроку они не нужны (DECISIONS №85).

Формат записи пчелы в протоколе (`sensors.py`): `{time, me: {id, kind, pos, energy, energy_max, cargo,
cargo_max, in_hive, auto_home, epoch, wait?, found?}, home, flowers: [{id, pos, nectar, spider?}],
bees: [{id, pos, team}], messages: [{from_id, word, where, from}], smell: [4], smell_way: [4][2]}`;
позиции абсолютные. Пчела в улье: позиция летка, пустые `flowers`/`bees`, сообщения — как у летка.

**Шум сенсоров** (`sensor_noise: true` в матче): гауссов шум позиций σ=0.3 м, из `rng("sensor_noise")`.
Выключен в песочнице, включён в соревновательных пресетах.

### 5.2 Связь
- `say(слово, место)` (DECISIONS №87): слово до 20 букв (`comms.max_word`) и необязательное место,
  до 4 сообщений за тик (`comms.max_say`). Доставка на следующем тике всем своим в радиусе связи
  15 м от точки отправки; пчёлы в улье находятся у летка (слышат сказанное в 15 м от летка, их
  сообщения звучат у летка); улей слышит, если леток в радиусе. Только свой улей.
- `heard` копит услышанное в раннере: сообщение видно с тика прихода до конца следующего прохода
  `loop()` (пока пчела ждёт команду, ничего не теряется); от каждого отправителя — последнее
  сообщение с каждым словом. Сообщение: `.word`, `.where`, `.from_where`.
- **Феромоны:** у каждого улья своя 2D-сетка, клетка 2 м, 4 канала — цвета `red`, `blue`, `green`,
  `yellow`; `mark` добавляет 1 в клетку под пчелой, испарение с полураспадом 60 с.

### 5.3 Улей
- `Hive`: `honey`, `time`, `count(тип)`, `heard` (сообщения в радиусе связи летка).
- В протоколе `team_view`: `{time, honey, nectar, counts: {scout: {in_hive, flying}, forager, house: n},
  busy (живые + личинки), max_bees, costs, messages, notes}`; `notes` — отказы `hatch` прошлого тика,
  раннер пишет их в лог игрока.

## 6. Погода (`weather.enabled`)

Марковская цепь состояний на тике решений: за тик `dt` переход с вероятностью `dt / mean_duration_s` (90 с) в одно из других состояний поровну; при смене заново выбирается `w_ref` из диапазона состояния; событие `weather`. Случайность — отдельный поток `rng("weather.chain")` (DECISIONS №42). Старт — `weather.initial`.

| Состояние | Базовый ветер `w_ref`, м/с | Дождь |
|---|---|---|
| clear | 0–1 | нет |
| windy | 1.5–3 | нет |
| rain | 1–2 | да |

Переключатели (DECISIONS №38): `enabled: false` — весь матч `clear`, ни ветра, ни дождя, ни смен; `wind: false` — без ветра (смены и дождь остаются); `rain: false` — состояние `rain` не наступает.

## 7. Враги (PvE)

Шершней и охранников в игре нет (DECISIONS №82). Остались пауки — правило мира в `enemies.py`
(DECISIONS №89; боты на API игрока, №36, больше не нужны: в API M8 классов врагов нет).

### 7.1 Пауки (`enemies.spiders.enabled`)
- 10% цветов с пауком (выбор по seed). Паук неподвижен.
- Сборщик, собирающий на таком цветке (набирает нектар на этом тике): вероятность гибели 0.15 за
  секунду — на тике решений `1 − 0.85^dt`, кубик из `rng("spiders")` по порядку слотов.
- Видит паука только разведчик ближе 4 м по горизонтали (поле `spider` у цветка). Передать знание
  остальным — задача кода игрока (`say`, запахи).

## 8. Матч и счёт

- `duration_s` (демо — 300 с), тик решений 10 Гц.
- **Победа:** больше мёда на складе в конце. Тай-брейки: весь доставленный нектар → живые пчёлы.
- **Выбывание:** нет живых пчёл, или нет летающих (и летающих личинок) и мёда меньше цены самой дешёвой летающей пчелы (DECISIONS №40). Выбывшие — ниже всех в таблице. Места — только у ульев со скриптом.
- **Досрочный конец:** из ≥ 2 ульев остался один (или выбыл единственный).
- Счёт по ульям: `place, honey, nectar, delivered, processed, scout, forager, house, alive, eliminated` и гибели `deaths_energy`, `deaths_spider`.
- События в реплей: `birth`, `death` (`cause`: `energy` / `spider`), `delivery`, `weather`, `eliminated`.

## 11. Примеры для игроков (`examples/bees/`)

- `template.py` — шаблон с подробными русскими комментариями: что такое `loop`, что знает пчела, какие есть команды.
- `example_basic.py` — разведчики ищут цветы и рассказывают («flowers» и место), сборщики слушают и собирают, полные — домой; улей выводит сборщиков, пока есть мёд.
- `example_smart.py` — разведчики сообщают поляны и пауков; сборщики выбирают цветок по нектару и расстоянию, обходят пауков и делят поляны; улей пересказывает поляны, держит число домашних под поток нектара и меняет порог возврата по времени матча.
- `example_blocks.blocks.json` (+ сгенерированный `example_blocks.py`) — то же, что `example_basic`, собранное из блоков.
