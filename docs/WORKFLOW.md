# Как вести проект с Claude Code (инструкция для Лео)

Этот файл для тебя, не для Claude Code.

## 0. Один раз: подготовка

1. **Python 3.11 или 3.12** с python.org, при установке отметить «Add python.exe to PATH». Проверить в новом PowerShell: `python --version`.
2. **Git for Windows** (git-scm.com). Claude Code тогда сможет пользоваться Git Bash; без него он работает через PowerShell — тоже нормально.
3. **Claude Code** в PowerShell:
   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```
   Открыть новый терминал, проверить `claude --version`. Нужна подписка Pro/Max (на бесплатном плане Claude Code нет). Первый запуск `claude` попросит войти через браузер.
4. **Репозиторий:**
   ```powershell
   cd D:\Files\Projects\swarmlab
   git init
   git add .
   git commit -m "docs: спецификация SwarmLab (ядро + пчёлки)"
   ```
   Дальше пушишь на GitHub сам, когда захочешь.

## 1. Цикл одной вехи (каждый день)

1. Открыть PowerShell в `D:\Files\Projects\swarmlab`, запустить `claude`.
   Если это продолжение вчерашнего разговора — `claude --continue`; новая веха — всегда новая сессия.
2. Включить **режим планирования**: `Shift+Tab`, пока внизу не появится `⏸ plan mode on`.
3. Написать:
   ```
   Выполни веху @prompts/M0.md
   ```
   (`@` подставляет файл; меняй M0 на текущую.)
4. **Проверить план.** Смотри на три вещи:
   - не тянет ли он лишнего из других вех;
   - соблюдает ли инварианты из `CLAUDE.md` (ядро не знает о пчёлах, MuJoCo только в `bees/physics`, векторный горячий цикл, код игрока только в раннере);
   - есть ли в плане тест на каждый критерий приёмки из `ROADMAP.md`.
   Если что-то не так — скажи текстом, пусть переделает план. Когда всё ок — одобри план (выйди из режима планирования, Claude начнёт писать код).
5. Пока работает — можно отойти. Прервать, если пошёл не туда: `Esc`.
6. **Приёмка.** Claude покажет вывод тестов, RTF, команды. Ты сам:
   - запускаешь команды из его отчёта (особенно `--mj-viewer` и браузер с M4);
   - проходишь ручной чек-лист из промта вехи;
   - ставишь ✅ в `docs/ROADMAP.md`.
7. **Коммит:** можно попросить Claude: «сделай коммит с этим текстом». Пушишь сам.
8. Следующая веха — `/clear` (очистить контекст) или новый запуск `claude`.

## 2. Если что-то идёт не так

| Ситуация | Что делать |
|---|---|
| Сессия стала длинной, Claude «забывает» | `/compact` или новая сессия: «продолжи веху M2; сделано: …; осталось: …» |
| Claude хочет поменять решение из документов | Это нормально, если есть причина. Пусть объяснит; если согласен — «обнови DECISIONS.md и профильный документ» |
| Тест не проходит третий раз подряд | «Остановись. Опиши гипотезы причины и как проверить каждую» — не давай ему бесконечно править вслепую |
| `pip install mujoco` падает | Почти всегда версия Python. Поставь 3.11/3.12 и пересоздай `.venv` |
| RTF < 1 на «Среднем» | «Профилируй cProfile, покажи топ-10, исправь» — частая причина: цикл по пчёлам на Python в шаге физики |
| Веха съезжает больше чем на полдня | Режем M5 (редактор), M6 оставляем как буфер |

## 3. Claude Code в вебе — когда пригодится

После того как репозиторий на GitHub, веб-версию удобно использовать для **изолированных параллельных задач**, которые не требуют твоего экрана и Windows:
- доработать `example_smart.py`;
- дописать юнит-тесты экономики;
- обновить README.

Каждая такая задача — отдельная ветка; сливаешь, когда проверил. Не давай вебу и CLI одновременно править одни и те же файлы. Всё, где нужно смотреть глазами (MuJoCo-вьюер, браузер, FPS) или проверять Windows-специфику — только локальный CLI.
