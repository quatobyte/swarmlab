# Как вести проект

Инструкция для Лео: как продолжать работу в существующем репозитории и принимать изменения. Правила для помощников — в `AGENTS.md`, текущая веха и критерии приёмки — в `docs/ROADMAP.md`.

## 1. Открыть проект

Весь код ядра и пчёлок находится в `D:\Files\Projects\swarmlab` (`master`). Город и карьер пока только идеи в документах (DECISIONS №99).

Перед задачей в нужной папке:

```powershell
git branch --show-current
git status --short
```

Если есть незакоммиченная работа, сначала отдели её от новой задачи: что уже сделано, какие проверки остаются, какие файлы можно менять. При продолжении сохраняй существующие изменения.

У проекта своё `.venv`, установленное из этой папки. Подготовка окружения — в `README.md`. Проверки можно запускать без активации:

```powershell
.\.venv\Scripts\python.exe -m pytest -rs
.\.venv\Scripts\python.exe -m ruff check .
```

Для JavaScript-проверок нужен Node.js в `PATH`. Пропущенная проверка не подтверждает работоспособность: причину пропуска и способ отдельного запуска указываем в отчёте.

## 2. Выполнить задачу или веху

1. Прочитать `AGENTS.md`, текущий раздел `docs/ROADMAP.md` и промт вехи. Для небольшой уборки отдельно назвать границы задачи; она не означает завершение всей вехи.
2. Показать план до правок: какие файлы меняются, какое поведение сохраняется, чем проверить результат. Для вехи каждому критерию приёмки соответствует тест или воспроизводимая команда. Если промт требует согласования плана, дождаться его.
3. Реализовать согласованный объём. Расхождение с принятым решением сначала обсудить; после согласования обновить `docs/DECISIONS.md` и профильный документ.
4. Запустить `pytest` и `ruff check`, затем проверки задачи: CLI, браузер, детерминизм или производительность. Показать результат, включая ошибки, пропуски и непроверенные пункты.
5. Проверить итоговый diff: новые изменения должны соответствовать плану, прежняя работа — сохраниться. Для вехи обновить проверенные пункты ROADMAP; ✅ ставит Лео после приёмки.

Следующую веху начинаем отдельной задачей. Частично реализованная веха остаётся в работе, даже если отдельные тесты зелёные.

## 3. Коммиты

Коммиты и push Лео делает сам. Помощник оставляет изменения в рабочем дереве и предлагает текст коммита.

Изменения ядра и пчёлок проверяются вместе в `master`. Проверки включают настоящие матчи и, когда уместно, браузер.

## 4. Продолжение и параллельная работа

В конце задачи сохраняем краткую передачу: ветка, изменённые файлы, результаты проверок, оставшиеся пункты и следующая команда. При продолжении сверяем это с текущим `git status` и ROADMAP.

Параллельным исполнителям назначаем разные файлы или обзор без правок. Все изменения остаются в одном рабочем дереве.

Если проверка повторно падает, сначала фиксируем воспроизведение и гипотезу причины. Если нужна ручная проверка на машине Лео, оставляем точную команду и ожидаемый результат; такой пункт остаётся открытым до проверки.
